# Калькулятор Кзи и Узи

Самопроверка по двум методикам Федеральной службы по техническому и экспортному контролю (ФСТЭК России) в интерфейсе CheckU (Уральский центр систем безопасности, УЦСБ). Режим выбирается переключателем вверху страницы.

- Кзи: https://gleb-dvornikov.github.io/kzi-calculator/#kzi
- Узи: https://gleb-dvornikov.github.io/kzi-calculator/#uzi

## Возможности

Показатель защищенности (Кзи):

- Методика оценки показателя состояния технической защиты информации (утв. ФСТЭК России 11.11.2025), Требования, утвержденные приказом ФСТЭК России от 11.04.2025 № 117
- 16 показателей в 4 группах, формулировки дословно по таблице 1 Методики
- критерии с порогом в процентах заполняются числами: «привилегированных 40, из них со вторым фактором 18» дает 45%, критерий не выполнен
- неприменимость по сноскам Методики, условия обнуления групп (примечание к таблице 1 и п. 35)
- перечень «Что мешает получить Кзи = 1» по убыванию вклада показателя
- необязательные подтверждающие документы по каждому показателю: попадают в текущий отчет и в приложение к письму
- письмо во ФСТЭК России и текущий отчет в формате Word (.docx)

Уровень зрелости (Узи):

- Методика оценки уровня зрелости деятельности в области технической защиты информации (утв. ФСТЭК России 07.08.2026)
- 21 направление, по каждому 8 видов требований с вариантами ответа дословно по таблице 2
- уровень направления по таблице 3, Узи как среднее уровней направлений, уровень зрелости по таблице 1, целевой уровень по п. 11, исключение неприменимых направлений по п. 13
- отчет по составу п. 35 Методики и текущий отчет в формате Word (.docx)

Общее:

- реквизиты спрашиваются при нажатии «Сформировать отчет»
- напоминание о следующей оценке файлом календаря .ics: Кзи через 6 месяцев, Узи через 2 года
- «Сохранить в файл» и «Загрузить из файла»: ответы и реквизиты в JSON на компьютере пользователя
- предложение помощи УЦСБ под результатом: письмо на cybersec@ussc.ru открывается в почтовой программе пользователя

Данные никуда не отправляются. Ответы хранятся в localStorage браузера, сервера у калькулятора нет.

## Разработка

Нужен Node.js 22 (версия в `.nvmrc`).

```bash
npm install          # первый запуск создаст package-lock.json, его нужно закоммитить
npm run dev          # http://localhost:5173 с пересборкой при изменениях
npm run typecheck    # TypeScript в строгом режиме
npm test             # модульные тесты (node:test)
npm run test:e2e     # сквозные тесты в Chromium (Playwright), перед ними собирается dist/
npm run format       # Prettier
npm run check        # типы, форматирование, тесты и сборка одной командой
```

Перед первым запуском e2e-тестов: `npx playwright install chromium`.

## Устройство

React 19, TypeScript, сборка esbuild, стили CSS Modules. Отчеты строит библиотека docx, она загружается отдельным файлом только при формировании отчета.

```
src/
  domain/              Методики и расчеты без React: можно проверять тестами
    kzi/               показатели Кзи, критерии, обнуление групп, расчет
    uzi/               направления, виды требований, таблица 3, расчет Узи
    fstec.ts           управления ФСТЭК России и их руководители (адресаты письма)
    requisites.ts      поля реквизитов и проверка
    offer.ts           текст предложения помощи и письмо в УЦСБ
    schedule.ts        периодичность оценки
  state/               состояние приложения
    reducer.ts         все изменения состояния
    normalize.ts       проверка сохраненных данных и перенос ответов из версий 2 и 3
    storage.ts         localStorage
    file.ts            «Сохранить в файл» и «Загрузить из файла»
    store.tsx          React-контекст и хуки
  reports/             отчеты
    model.ts           простая модель документа (абзацы, списки, таблицы)
    kziReports.ts      письмо во ФСТЭК России и текущий отчет по Кзи
    uziReports.ts      отчет по п. 35 Методики и текущий отчет по Узи
    renderDocx.ts      модель документа -> .docx
    ics.ts             напоминание в календарь
  features/kzi, uzi/   экраны режимов
  components/          общие элементы интерфейса
  app/                 каркас страницы, панель результата, реквизиты, сообщения
  styles/              токены CheckU, шрифт, базовые стили
  assets/              логотип, шрифт Montserrat (лицензия OFL в assets/fonts/OFL.txt)
tests/                 модульные тесты
e2e/                   сквозные тесты и проверка верстки 360-1920 px
scripts/               сборка, сервер разработки и просмотра
```

Принципы:

- расчеты и тексты Методик лежат в `src/domain` и не зависят от интерфейса
- значения хранятся целыми числами в долях (Кзи 10000 = 1, Pзн 1000 = 1), чтобы не было ошибок округления
- отчеты сначала описываются моделью документа: ее содержание проверяют тесты, оформление .docx задано в одном месте
- в текстах интерфейса и отчетов нет буквы «ё» и обозначений «КЗИ»/«УЗИ», это проверяет `tests/content.test.ts`

## Данные, которые устаревают

- `src/domain/fstec.ts`: руководители управлений ФСТЭК России. Проверены 07.10.2026, перед отправкой письма адресата нужно сверить на fstec.ru. В форме реквизитов руководителя можно исправить вручную.
- Ссылки на методики и пункты приказов в `src/domain/*/methodology.ts` и в справочных блоках `src/features/*/*Info.tsx`.

## Публикация

GitHub Pages публикует корень ветки `main`. Собранный сайт лежит в корне репозитория рядом с исходниками:

```bash
npm run build:pages   # пересобирает index.html, assets/, favicon.svg и .nojekyll в корне
```

Эти файлы создаются сборкой, руками их не правят. После `npm run build:pages` их нужно закоммитить вместе с изменениями исходников.

Для переноса на домен УЦСБ подойдет любой веб-сервер статических файлов (например nginx с TLS): `npm run build` собирает сайт в `dist/`, содержимое папки копируется на сервер.

## Проверки
